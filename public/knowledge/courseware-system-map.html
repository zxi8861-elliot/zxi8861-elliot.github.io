02.1 / 先用一个例子看懂

BEGINNER START

如果你第一次看这个项目，不要先读代码名。先把它想成一位“备课助理”：你给它一个教学目标，它负责查资料、列课纲、写每个场景，再把结果交给浏览器播放。

例子：给五年级学生做《月相变化》互动课件

用户说：“请用适合五年级的方式，讲清楚月相为什么每天不同，并加入一个可以拖动日期观察月相的互动。” 这句话不会直接变成一张网页，而是会经过下面五个中间对象。

一句话先记住

Query 是需求，Scene 是一个可播放的课件场景，Runtime 是把场景真正运行起来的播放层。

一句话需求 → 研究上下文 → 课程大纲 → Scene → 浏览器课堂

01 / INPUT

用户说需求

主题、学生年龄、教学目标和想要的互动。

02 / CONTEXT

系统找资料

读取教材或联网搜索，整理成模型能使用的上下文。

03 / PLAN

AI 列课纲

决定课程标题、知识点顺序和每个 Scene 的类型。

04 / SCENE

AI 写课件

为每个场景生成内容、教学动作和图片/声音引用。

05 / PLAY

浏览器运行

Renderer 显示页面，PlaybackEngine 驱动时间轴，ActionEngine 执行动作。

先看懂这 5 个词

QUERY用户提出的课程需求。
RUN一次完整的生成任务。
SCENE一页或一个互动课件场景。
ASSET被课程引用的文件或媒体。
ACTION课堂中的讲解、聚焦和等待动作。

推荐阅读顺序

  1. 先看本例，建立“需求变课堂”的整体印象。
  2. 再看主生成链路，理解 Query 如何变成 Scene。
  3. 再看调用时序，理解前端、后端、AI 和数据库谁调用谁。
  4. 再看播放与互动，理解 Scene 如何在浏览器里运行。
  5. 最后看恢复、安全和代码索引，进入工程细节。

05 / 前端、后端与 AI

CALL & CALLBACK

生成任务通过 202 响应创建，再由 Runner 后台执行。浏览器不等待一个超长请求，而是通过 SSE 持续收取进度。

BROWSER → API提交 POST /api/generation-runs，收到 202 + runId。
API → DB创建 Generation Run，绑定 ownerId，保存输入和初始状态。
RUNNER → AIRunner 按顺序调用 research、outline、scene-content、scene-actions。
AI → RUNNER模型返回文本或 JSON；服务端解析、规范化、校验，然后写入 checkpoint。
DB → SSE推送 outline_item、scene_ready、step_retry 和完成事件。
SSE → UI前端更新进度、显示大纲、挂载新场景，用户可以实时看到课程长出来。
01 / HTTP 202

创建异步任务

POST /api/generation-runs 只返回 runId 和初始状态，浏览器不阻塞等待整堂课。

02 / SSE

服务端进度回调

EventSource 读取持久化事件，例如 research_sources、outline_item、scene_ready、step_retry、completed。

03 / MODEL STREAM

模型流式回调

Runner 从流中识别 courseTitle、languageDirective 和完整 outline object，先写 checkpoint，再转成 SSE。

04 / CALLBACK RULE

回调不是直连

模型不直接回调浏览器；AI → Runner → DB checkpoint → API → SSE → UI，所有进度都经过服务端边界。

07 / Generation Run 状态机

STATE / LEASE / RETRY

每个阶段都有 stepId 和 checkpoint。Worker 使用 lease 防止任务重复执行，失败时只重跑当前阶段，不丢失已经完成的场景。

准备

识别用户、检查能力、解析资料、执行搜索。

大纲

02 / GENERATE

生成

逐场景执行 content → actions → narration。

03 / PAUSE

暂停 / 重试

记录失败原因，从失败步骤继续。

04 / COMPLETE

完成

课程文档和资源引用写入持久化存储。

08 / AI 调用矩阵

INPUT / OUTPUT

输出搜索关键词 / web-search-query-rewrite
OUTLINE
输入需求、搜索结果、资料、教师上下文

SCENE CONTENT

SCENE ACTIONS

CLASSROOM AGENT
输入学生问题、当前 Scene、工具和历史
输出角色回答、工具调用、继续/结束信号

10 / 模型能力与资料路由

CAPABILITY / PROVIDER / MATERIAL

系统不是固定调用一个模型。它先看当前能力槽位，再决定是否能搜索、是否能看图、是否能生成媒体，以及每一步该使用哪个 Provider。

01 / REQUEST需求 + 设置interactive、taskEngine、learnerProfile、materials
02 / CAPABILITY能力检查outline、content、vision、tts、image、video
03 / SLOT模型槽位按阶段解析 model、Provider、Key、Base URL
04 / FALLBACK降级策略备用模型、纯文本模式、跳过不可用媒体
MATERIAL上传文件 → assetId → 提取文本 / 图片 / 转写 → 注入 outline 和 scene prompt。
WEB SEARCHRequirement → Query rewrite → 搜索 API → context + sources → 大纲 Prompt。
VISION检查 vision 能力 → 解析图片 asset → 按上限裁剪 → 图片和文字描述一起进入模型。

12 / 资料与资源生命周期

UPLOAD → REFERENCE → CLEANUP

教材、图片、音频、视频和生成 HTML 都以 Asset 管理，不是散落在 Scene 里的字符串。

01 / UPLOAD上传资源文件、教材、图片、音视频
02 / ASSET分配 assetId记录类型、来源、owner 和状态
03 / PROCESS解析或生成文本提取、关键帧、转写、媒体生成
04 / REFERENCEScene 引用Media Refs、suggestedImageIds、audioId
05 / CLEANUP引用对账删除课程后清理未引用或失效资源
01 / TEXT

文本提取

PDF / Word / PPT → 可搜索文本 → 材料摘要 → outline prompt。

02 / VISUAL

图片与关键帧

文档图片或视频关键帧 → image asset → suggestedImageIds / vision context。

03 / AUDIO

音视频转写

音频 / 视频 → transcript asset → 作为课程上下文或字幕候选。

04 / REFERENCE

引用与清理

Scene 保存 assetId；版本替换后做资源对账，删除无引用资源。

13 / 媒体辅助管线

TEXT / AUDIO / IMAGE / VIDEO

字幕、声音、图片和视频不完全阻塞主生成流程。大纲先提出需求，媒体编排器再异步生成资源、保存 assetId、替换占位符。

01 / SPEECH

字幕 → TTS

speech.text → 已配置的服务端 TTS 或已启用的 browser-native-tts → 播放时间轴；未启用时按阅读时长推进。

02 / IMAGE

图片 → Scene

教材图片优先；缺失时 image request → 生成 → assetId → 替换 gen_img。

03 / VIDEO

视频异步任务

提交任务 → 轮询状态 → 保存媒体资源 → 插入目标 Scene。

01 / SPEECH

生成 speech action

Scene content → speech.text → 播放时间轴字幕

02 / SERVER TTS

服务端语音

Runner → /api/generate/tts → 音频文件 → audioId

03 / BROWSER TTS

浏览器原生朗读

没有预生成音频且用户选择并启用 browser-native-tts 时，PlaybackEngine → SpeechSynthesis → 朗读文本；否则按阅读时长继续。

04 / CAPTION

字幕显示

speech.text 与动作时间轴同步；有字幕不代表一定有声音

05 / IMAGE

教材图片优先

检查 suggestedImageIds → 提取教材图片 → Scene 引用

06 / IMAGE FALLBACK

SVG / CSS / 生图

没有教材图 → SVG/CSS 或 image request → 保存图片 Asset

07 / VIDEO

创建视频任务

判断能力 → media manifest → /api/generate/video

08 / POLL

完成后插入 Scene

异步生成 → 轮询 → asset → video element → 重新渲染

01
字幕
speech.text 进入播放时间轴，跟随动作显示。字幕可以存在，但没有 TTS 音频时不会自动发声。
02
声音 / TTS
服务端 TTS 生成 audioId；没有预生成音频时，PlaybackEngine 只有在用户启用 browser-native-tts 后才会调用 SpeechSynthesis，否则只按阅读时长推进。音频作为资源被 speech action 引用。
03
图片
优先使用教材图片；不足时创建 image request，调用 /api/generate/image，生成后替换 gen_img。
04
视频
提交异步视频任务，轮询状态，完成后保存 asset，再插入指定 Scene。视频比文本生成多了一层任务生命周期。

15 / Scene 如何被运行

CONTENT → RENDERER → PLAYBACK

AI 输出的 JSON 不是最终画面。Renderer 根据 Scene 类型选择渲染器，PlaybackEngine 驱动动作时间轴，ActionEngine 执行具体的讲解、聚焦、白板和互动控制。

01 / DATA

读取 Scene

读取 type、content、actions、media refs 和当前播放位置。

02 / ROUTE

选择 Renderer

slide、quiz、interactive、pbl 分别进入不同渲染路径。

03 / PLAY

执行 Actions

speech、highlight、wait、quiz interaction 组成课堂节奏。

04 / BRIDGE

控制 iframe

React 通过 postMessage 控制互动 HTML，并接收 ready / error / state。

16 / 互动 HTML 的运行逻辑

SCENE JSON / REACT / IFRAME / STUDENT

互动课件不是 React 每次点击都重新渲染一个按钮，而是由宿主页面装载一份受沙箱保护的 HTML；互动发生在 iframe 内部，状态和控制指令通过 postMessage 往返。

核心结论：React 负责装载和控制互动页面；沙箱 iframe 负责执行 HTML/CSS/JavaScript 和维护内部交互状态；学生事件通过 postMessage 返回宿主，宿主再把状态、错误和教学控制同步回课堂。

17 / 错误、重试与降级

FAILURE / RETRY / DEGRADE

系统不会把所有失败都当成同一种错误：模型失败可以重试，媒体失败可以延后，结构校验失败必须阻止写入。

01 / DETECT捕获错误请求、Schema、媒体、Worker
02 / CLASSIFY判断错误类型可重试、可降级、必须暂停
03 / RECOVER重试或切换fallback、局部重跑、媒体异步补偿
04 / CHECKPOINT恢复运行保留已完成结果，从失败步骤继续
MODEL FAILURE

模型请求失败

同一模型重试；连续失败后切换 fallback model；仍失败则暂停 Run，保留已完成 checkpoint。

SCHEMA FAILURE

结构校验失败

Scene 不符合 schema 时不会进入课程文档，当前 scene 重新生成，避免脏数据污染播放层。

MEDIA FAILURE

图片 / 视频失败

媒体可以独立重试，不必让整个课程回滚；占位符和资源引用保持可追踪。

LEASE FAILURE

Worker 中断

释放或丢失 lease 后，其他 Runner 可以继续领取任务，从最近 checkpoint 恢复执行。

18 / 编辑、重生成与资源回收

EDIT / REGENERATE / RECONCILE

课程完成不是流程终点。用户可以只修改一个场景、一个动作或一条字幕，系统只重建受影响的部分。

01 / EDIT用户修改文本、排序、动作、字幕、互动配置
02 / SNAPSHOT保存旧版本保留当前 Scene 和资源引用
03 / REGENERATE局部调用 AI只重生成目标场景或 actions
04 / APPLY校验并替换content validation → store update
05 / RECONCILE资源对账清理失效图片、音频、视频引用

19 / 多租户与安全边界

OWNER / SANDBOX / ALLOWLIST

这是“多人正式使用”必须理解的一层：每个请求先确定 owner，再限制数据、资源和工具的可见范围。

01 / REQUEST请求进入登录会话或匿名 owner
02 / OWNER确定数据边界ownerId 限制课程、素材、设置
03 / TOOLS限制 Agent 能力allowlist 只开放当前工具
04 / SANDBOX隔离运行iframe + postMessage + Schema
OWNER请求 → 登录用户或匿名 owner → 所有课程、素材、设置按 ownerId 隔离。
TOOLSAgent Runtime 使用 allowlist，只能调用当前会话声明过的工具。
IFRAMEAI 生成 HTML 运行在 sandbox iframe，通过 postMessage 与宿主通信。
VALIDATE模型返回的 Scene 必须通过 schema 校验，未通过就不能写入课程。
